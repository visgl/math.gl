Overview

@math.gl/geospatial provides ellipsoid geometry, geographic/Cartesian conversions, local tangent frames, globe queries, and tile-grid geometry. Use it for WGS84 positions and 3D Tiles bounds without a renderer dependency.

Geographic arrays use [longitude, latitude, height], with angles in degrees and ellipsoidal height in metres by default. Cartesian arrays use Earth-centered coordinates in metres. Geoid heights and general CRS conversion are handled by geoid and projection.

The geospatial group includes @math.gl/geospatial, /globe, /tiles, /crs, /projection, /web-mercator, /wkb, /geoarrow, and /expressions. @math.gl/web-mercator remains available for existing imports. DGGS remains a separate package.

New to these concepts? Start with Geospatial terminology for geodesics, rhumb lines, chords, ellipsoids, reference systems, and projection properties.

Feature support​

A geospatial mathematics checklist spanning surfaces, reference frames, and global paths.

Support describes the public API in the current repository. Notes identify limits and experimental features.

Usage​

Determine the Cartesian representation of a Cartographic position on a WGS84 ellipsoid.

import {Ellipsoid} from '@math.gl/geospatial';
const cartographicPosition = [21, 78, 5000]; // [longitude, latitude, height]
const cartesianPosition = Ellipsoid.WGS84.cartographicToCartesian(cartographicPosition);

Determine the Cartographic representation of a Cartesian position on a WGS84 ellipsoid.

import {Ellipsoid} from '@math.gl/geospatial';
const cartesianPosition = [17832.12, 83234.52, 952313.73];
const cartographicPosition = Ellipsoid.WGS84.cartesianToCartographic(cartesianPosition);

Get the transform from a local east-north-up frame at a point on the WGS84 ellipsoid to Earth's fixed frame.

import {Ellipsoid, eastNorthUpToFixedFrame} from '@math.gl/geospatial';
const cartesianOrigin = Ellipsoid.WGS84.cartographicToCartesian([21, 78, 0]);
const transformMatrix = eastNorthUpToFixedFrame(Ellipsoid.WGS84, cartesianOrigin);

Framework Independence​

Input coordinates can be numeric arrays; callers do not need to construct core vectors.

  • Coordinate inputs and outputs use three-component numeric arrays. Check each method's result parameter before supplying reusable storage.

History​

This library was initially created as part of a bigger collaboration between the vis.gl and Cesium teams to provide framework-independent, portable support for the 3D Tiles specification, however it has been designed to provide generic support for WGS84 and ellipsoidal math.

Attribution​

Selected classes and three-radius ellipsoid kernels derive from Cesium under Apache-2.0. Shared spheroid conversion kernels also retain proj4js MIT provenance. Source headers and distributed notices identify the applicable credits and terms.

Globe queries​

EllipsoidOccluder and globe horizon bounds provide true ray intersections, elevated-point occlusion, exact limb ellipses and wrapped conservative imagery coverage without a viewport or rendering dependency.

Globe mesh subdivision​

subdivideGlobeMesh refines triangulated longitude/latitude meshes onto a sphere or oblate ellipsoid, preserving shared edges and attribute provenance. Import it and SubdivideGlobeMeshOptions from @math.gl/geospatial.

Tile matrices​

Tile matrix types and utilities describe supplied rectangular grids in any coordinate system. Import from @math.gl/geospatial for a lightweight entry point with no runtime dependencies. Helpers provide bounds, coordinate lookup, compact extent-to-tile ranges, coverage checks and resolution-based level selection.

Use the geographic tile helpers above for the built-in equal-angle longitude/latitude quadtree and antimeridian-aware queries. Explicit matrix queries use half-open edges and never wrap.

Local frames and poses​

LocalReferenceFrame separates point and vector transformations, composes geographic heading/pitch/roll poses, and builds velocity-aligned orientations. Import it from @math.gl/geospatial. Local distances use the ellipsoid axis units; pose angles use radians.

Geodesic path sampling​

GeodesicPath reuses a shortest geodesic line for fraction/distance sampling. subdivideGeodesicPolyline adaptively maps those paths through a supplied transform with original-edge provenance and optional surface-distance limits. Source angles are degrees, output tolerance uses target units, and longitude unrolling does not split projection seams. Import the sampler from /ellipsoid and subdivision from /globe.

Local-frame qualification and G7 benchmark baselines document the supported numerical profile and independent/native evidence.

Wider-domain and triaxial geodesics​

  • EllipsoidGeodesicExact: optional elliptic direct/inverse revolution geodesics and reusable distance/arc lines.
  • TriaxialEllipsoid: three surface coordinate systems, direction conversions and reusable Cartesian geodesic trajectories.
  • G8/G9 qualification and support limits.

Optional coordinate utilities provide angle text and WGS84 UTM/UPS/MGRS cells. Packed line sampling adds reusable geodesic/rhumb output storage. Triaxial geometry also supports area-uniform surface points.
