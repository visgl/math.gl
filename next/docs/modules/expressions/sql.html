@math.gl/expressions/sql 🧪

Import @math.gl/expressions/sql to parse supported SQL statements into portable query and predicate objects. The application supplies data and executes the query. The parser works without Apache Arrow.

Submodule features​

FeatureSupportNotes
Query parsing✅parseSQLQuery() parses SELECT statements and supported catalog commands.
Structural-only parsing✅parseSQLSelect() parses projection, source references, and limits without the built-in predicate parser. Supply parseWhere to enable WHERE.
Standalone predicate parsing✅parseSQLPredicate() parses the expression after WHERE.
Named parameter binding✅Predicate parsing can bind values immediately or preserve parameter references for bindSQLPredicate().
Predicate validation✅validateSQLPredicate(), isSQLPredicate(), and SQL_PREDICATE_JSON_SCHEMA validate portable predicates. The JSON Schema covers JSON-compatible values.
Portable TypeScript types✅Query, selection, table reference, catalog command, and predicate types contain no data sources or execution controls.
Optional, tree-shakeable imports✅Separate SQL subpath; structural parsing does not require the built-in predicate parser.
Bounded parsing✅Input size, token count, and predicate nesting limits reject oversized input.
Query execution and source discovery❌Supplied by the consuming application, not this parser.
Arrow integration or database connections❌No Arrow, loaders.gl, or database dependency.
General-purpose SQL AST❌Output represents the supported query subset, not arbitrary SQL programs.

SQL syntax features​

✅ Supported · ⚠️ Restricted · ❌ Unsupported. These statuses describe parseSQLQuery(). See Relational SELECT below for the planner-oriented parser. An injected WHERE parser can define a different predicate language.

SQL featureSupportSyntax and limitations
Column projection✅SELECT city, population or SELECT *.
Column aliases✅SELECT city AS name; explicit AS is required.
Source and table references✅FROM cities or FROM warehouse.cities; FROM is optional.
Quoted identifiers✅Double quotes, including doubled quote escapes: "city""name". Identifier case is preserved.
Keywords and statement terminator✅Case-insensitive keywords and one optional trailing semicolon.
Comparisons⚠️Scalar expressions compared with =, !=, <>, <, <=, >, >=; includes column-to-column comparisons.
Boolean predicates✅AND, OR, NOT, and parentheses.
Membership✅IN (...) and NOT IN (...) with a nonempty list of scalar values.
Null tests✅IS NULL and IS NOT NULL; expression comparisons with NULL evaluate to unknown.
Scalar literals✅Numbers, single-quoted strings with doubled quote escapes, and Boolean values. Use null tests rather than NULL literals.
Named parameters⚠️:name in parseSQLPredicate(), with supplied values or preserved references. Use an injected WHERE parser for parameterized SELECT statements.
Pagination✅LIMIT followed by a nonnegative safe integer, including zero. OFFSET skips rows before the limit.
Catalog commands✅SHOW SOURCES, SHOW TABLES [FROM source], and DESCRIBE source[.table]. SHOW SOURCES is a parser-specific command.
Qualified column names❌SELECT table.column and qualified WHERE columns in parseSQLQuery() are rejected. Quote literal column names containing dots.
Computed columns and function calls⚠️CAST, postfix :: conversions, arithmetic + - * /, named functions, searched CASE, and fixed-size ARRAY expressions. Execution supplies registered functions.
Additional predicate operators❌No LIKE, ILIKE, BETWEEN, regular expressions, or EXISTS.
Sorting and pagination❌No ORDER BY or FETCH.
Aggregation and distinct rows❌No aggregate functions, GROUP BY, HAVING, or DISTINCT.
Joins and nested queries❌No joins, subqueries, CTEs (WITH), or set operations such as UNION.
Table aliases and qualified wildcards❌No FROM cities AS c or SELECT c.*.
Window functions❌No OVER or window definitions.
Data and schema changes❌No INSERT, UPDATE, DELETE, CREATE, or other mutation statements.
Comments and scripts❌No SQL comments or multiple statements.

Usage​

import { parseSQLQuery } from "@math.gl/expressions/sql";

const query = parseSQLQuery(
  "SELECT city AS name, population FROM warehouse.cities WHERE population >= 100000 LIMIT 10",
);

WHERE references source column names, before projection aliases are applied. For example, use WHERE city = 'Paris', not the output alias name.

For structural parsing with an explicitly supplied predicate parser:

import { parseSQLSelect, parseSQLPredicate } from "@math.gl/expressions/sql";

const query = parseSQLSelect("SELECT city WHERE population >= :minimum", {
  parseWhere: (expression) =>
    parseSQLPredicate(expression, {
      parameters: { minimum: 100000 },
    }),
});

Importing only parseSQLSelect lets a tree-shaking bundler omit the built-in predicate parser. Without parseWhere, this function rejects statements containing WHERE.

Relational SELECT​

Use parseSQLSelectStatement() when your application owns the query planner. It returns projection, source, join, filter, grouping, sorting, and pagination clauses without resolving names or executing the query.

import {parseSQLSelectStatement} from '@math.gl/expressions/sql';

const statement = parseSQLSelectStatement(
  'SELECT t.region, COUNT(*) AS total FROM trips AS t ' +
    'WHERE t.fare >= :minimum GROUP BY t.region ORDER BY total DESC NULLS LAST LIMIT 10',
  {parseParameter: name => ({type: 'Identifier', name: `:${name}`})}
);

The parser supports table aliases, qualified column references, INNER, LEFT, SEMI, and ANTI joins with ON conditions, GROUP BY, ORDER BY with optional null placement, LIMIT, OFFSET, and SQL line comments. Aggregate calls are expression nodes. COUNT(*) is a call with a wildcard identifier argument marked sqlWildcard: true. The caller validates the supported join conditions and aggregate functions and binds parameters. Use parseParameter to supply an expression node for each named parameter.

Expressions​

parseSQLExpression() returns the shared expression AST. Computed selections use {expression, as?}; computed WHERE clauses use {expression}. Existing portable predicate shapes remain unchanged for predicates accepted by parseSQLPredicate().

CASE WHEN condition THEN value ELSE fallback END evaluates only the selected branch. Unquoted function names resolve case-insensitively; quoted function names and column names retain their exact case. Use POWER(x, y) and MOD(x, y); SQL does not accept JavaScript **, ^, or %. JavaScript expression parsing remains available separately.

ARRAY[x + 1, SIN(angle), 0] has a fixed width known at compilation. Arrow evaluation infers the widest floating component type; integer-only arrays use Float64. Explicit casts such as ARRAY[x, y]::REAL[2] select Float16/32/64 precision and check finite overflow. Any null component produces a null tuple with zero-filled numeric padding. Variable-length result lists are deferred. SQL parsing and Arrow evaluation remain separate optional imports.

Parameters and validation​

Preserve parameter references when a predicate will be reused with different values:

import { parseSQLPredicate, bindSQLPredicate } from "@math.gl/expressions/sql";

const predicate = parseSQLPredicate("population >= :minimum", {
  preserveParameters: true,
});
const bound = bindSQLPredicate(predicate, { minimum: 100000 });

Binding returns a new predicate without modifying the template. Missing parameters and unsupported values throw. Runtime predicates support bigint, Date, and Uint8Array values in addition to JSON scalars; the exported JSON Schema describes only the JSON-compatible representation. validateSQLPredicate() throws on invalid predicates; isSQLPredicate() returns a Boolean.

Statements and standalone predicates are limited to 65,536 characters and 4,096 tokens per parser. Predicate nesting is limited to 64 levels. Unsupported syntax throws rather than being ignored.

Using a query engine​

Once a math.gl release containing this subpath is available, applications using loaders.gl's optional scan query API can inject the parser:

import { query } from "@loaders.gl/core/scan";
import { parseSQLQuery } from "@math.gl/expressions/sql";

const result = await query("SELECT city AS name WHERE population > 100000", {
  source: arrowTable,
  sqlParser: parseSQLQuery,
});

The parser can also be loaded on demand:

const result = await query("SHOW TABLES FROM warehouse", {
  sources,
  sqlParser: import("@math.gl/expressions/sql").then((module) => module.parseSQLQuery),
});

arrowTable and sources are application-provided inputs. The query engine resolves source names, validates columns, and executes the result. math.gl does not import loaders.gl, and moving the loaders.gl parser implementation to this package is a separate migration.

CAST expressions​

parseSQLExpression('CAST(value AS INTEGER)') returns a core expression AST suitable for compileArrowExpression from @math.gl/expressions/arrow. The optional SQL module itself has no Arrow dependency. SELECT CAST(value AS INTEGER) AS count returns a selection with an expression AST and as alias. Existing plain-column selections retain their shapes.

Supported SQL targets: SMALLINT, INTEGER/INT, BIGINT, REAL, DOUBLE PRECISION, BOOLEAN, VARCHAR, CHARACTER VARYING and FLOAT16. CAST accepts columns, scalar literals and nested expressions. WHERE CAST(value AS INTEGER) >= :minimum records ordered casts on the source property; executors must apply those conversions before testing the predicate. Binding, validation, copying and column discovery preserve this information. Arrow's predicate evaluator executes these casts.

Unsupported targets/modifiers fail explicitly. This subset does not accept DECIMAL, date/time, length/precision modifiers, or casts on scalar values in the portable predicate representation. See Arrow expression conversion rules.

Postfix value::TYPE and chained casts are also supported with the same conversion rules.

Packed floating-point arrays​

SELECT ARRAY[x, y, z] AS position returns {array: ['x', 'y', 'z'], as: 'position'}. Source-only selections retain this shape and require an alias. Computed arrays such as ARRAY[x + 1, SIN(angle), 0] AS position return {expression, as}. Use compileArrowArray(selection.array, {inputSchema, type: selection.type}) for the former, and compileArrowExpression(selection.expression, {inputSchema, functions}) for the latter.

The component type is the widest floating input, or Float64 for integer-only arrays. ::FLOAT16[3], ::REAL[3], and ::DOUBLE PRECISION[3] explicitly choose precision and require matching width. FLOAT32 and FLOAT64 are also accepted for fixed-array casts. Float16 execution requires native Float16Array. Null components make the whole tuple null, with zero numeric padding. GPU consumers must respect parent validity or invalid positions appear at the origin.

Executors can consume the portable expression AST and Arrow-independent numeric metadata.

ARRAY[r, g, b, a]::UINT8[4] and CAST(ARRAY[r, g, b, a] AS UINT8[4]) select byte storage. The parser checks the width and lowers both spellings to an array_uint8 call. PACK_UNORM8 is a separate call that scales normalized values. See Byte arrays and normalized packing.

Syntax errors​

Parser syntax errors use SQLParseError, a SyntaxError with a zero-based UTF-16 offset, one-based line and column, and a short token preview when a token is present. When parsing a complete statement, locations in the built-in WHERE parser refer to the original SQL text. Use the structured fields to highlight the location in an editor. Exceptions thrown by a custom WHERE parser are preserved.

Pass a probe.gl logger as the log option to parseSQLQuery to capture parser errors. The parser reports the diagnostic and throws the original error.
