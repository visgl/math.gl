GeographicLib G3–G4 qualification

This bounded increment adds EllipsoidMetrics, optional geodesic edge S12, and GeodesicPolygon. It does not replace the G0–G2 qualification or claim universal finite-input correctness, arbitrary-flattening geodesics, or full GeographicLib feature parity. G5/G6 and wider-domain Exact solvers remain separate work.

Controls and budgets​

The stored original workload has 810 cases: 336 native metric/latitude cases, 35 independent integral cases, 24 inverse edges, 48 direct/arc cases, 360 polygon/polyline cases, and seven independent spherical triangles (each at four length scales). Each case can gate several outputs. Node and Chromium, Firefox and WebKit run the same source-bundled evaluator. Contract tests also check all line entry paths, preview isolation, errors, reset, zero and ownership.

Existing accuracy/coverage/bundle limits are unchanged. New metrics are limited to 0.5 ≤ b/a ≤ 2 and reject nonrepresentable dimension results; they do not silently extrapolate a series beyond a qualified flattening range. Sphere, near-sphere, oblate/prolate and pole endpoint behavior is explicit in the API.

Independent mathematics and native discrepancies​

The standard-library Python generator uses 80-digit Decimal arithmetic, Machin π, Taylor trigonometry, and independently constructed 48-node Gaussian quadrature to evaluate the meridian and surface integrals. Production uses binary64 16-node quadrature with different subdivision. Independent inversion controls supply mathematical auxiliary values, not production round trips. Spherical excess of a right triangle is evaluated as 2 atan(tan(delta/2)^2) with high precision, including tiny areas.

For the tiny equatorial ellipsoidal triangles, the independent local metric integral is b² delta² / 2, multiplied by the loop count when applicable. The neglected relative curvature term is O(delta²), below 1e-12 for the stored shapes and delta ≤ 1e-5 degree, well below the 2e-8 gate. For short equatorial 45° direct edges the corresponding integral is distance² / 4; its neglected relative term is likewise below 1e-12. These are mathematical controls with bounded remainders, not native values promoted to exact expectations.

Native GeographicLib C++ 2.7, tag r2.7, archive SHA-256 5aaca14cd75f13aa2690273d76e88e8ddf4aeb267d6be2c3e0ba948deb9ceea5, is the comparator. Both its series and elliptic-integral Exact geodesics/polygons are recorded. The fixture records actual native significand precision (53 bits for the recorded Apple arm64 precision-3 build), driver/generator hashes and the complete native-data hash. A precision-3 build is not claimed to provide more than 53 significant bits on this platform.

Direct-edge transit parity uses the C++ centered-remainder convention. JavaScript % 720 has negative residues below -360; those belong to the even crossing class. Both directions across negative circuit boundaries are tested with longitude translations from -1440° through +1440°, against native series/Exact and an independent right spherical triangle. This fixes a half-surface area error which was invisible to normalized-longitude-only controls.

Polygon reduction uses the exact same cached authalic normalization as its edge engine. Recomputing a nominally equivalent total area independently caused a WebKit rounding residue at a degenerate zero-area boundary to select the full unsigned complement; this is fixed and regression-tested. Projection gnomonic uses the shared raw engine so optional public facade/area APIs are discarded from projection-only bundles. Existing bundle limits pass without increases.

Two native limitations are explicit:

  • Subtracting nearly equal C4 Fourier values loses tiny ellipsoidal area bits. Native series and Exact disagree, and both can disagree materially with the independent local integral. math.gl uses the cosine-difference identity, preserving the short arc before subtraction. Original native results remain stored and their discrepancies remain visible in reports; tiny-area gates use the independent mathematics. The 1,000-loop workload also checks compensated accumulation rather than allowing a global a² tolerance to hide small areas.
  • Near a pole, native Exact distance inversion can lose phase bits, amplified into area errors. Those explicitly annotated Exact distance results are diagnostic; native series remains a gate, and independent high-precision sphere controls validate the conditioned case. Arc calculations compare the identical stored arc, not a distance recast as an assumed equivalent input. Exactly 1440° and 8*pi*a in binary64 need not specify the same side of an exact pole. Different pole/antipodal branches are domain conventions, not silently widened error allowances.

No relative-area guarantee is claimed for arbitrary nearly cancelling, non-equatorial polygons or unbounded numbers of circuits. The ordinary absolute area budget remains visible. A sampled result is not an all-input proof.

Reproduction and CI​

# Ordinary CI: no native library, compiler, download or extra Python package.
python3 modules/geospatial/projection/scripts/generate-g34-reference.py --check
node modules/geospatial/projection/scripts/qualify-g34.mjs --output /tmp/g34.json
node modules/geospatial/projection/scripts/qualify-g34.mjs --browser chromium --output /tmp/g34-chromium.json

To regenerate native values, verify the pinned archive hash, extract r2.7 and build its static C++ library with GEOGRAPHICLIB_PRECISION=3 (for example CMake -DGEOGRAPHICLIB_PRECISION=3 -DBUILD_SHARED_LIBS=OFF). Compile the original geographiclib-g34-oracle.cpp driver with those generated/source include paths and that static library, using the same precision configuration. Then run:

python3 modules/geospatial/projection/scripts/generate-g34-reference.py \
  --archive /path/to/geographiclib-r2.7.tar.gz --oracle /path/to/g34-oracle
# Same compiler/precision environment can check exact regeneration:
python3 modules/geospatial/projection/scripts/generate-g34-reference.py \
  --archive /path/to/geographiclib-r2.7.tar.gz --oracle /path/to/g34-oracle --check

No upstream implementation or test dataset is downloaded by CI.
