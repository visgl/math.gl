# Switch projection engines

Applications written against math.gl's projection interfaces can still work with
external projection engines using this recipe: implement `ProjectionEngine`,
return a complete synchronous `PreparedProjection`, and inject the chosen engine
into the same application code.

## The recipe

The application calls `prepareMap(engine, mapName)` for the selected projection, then uses only `project()` and
`unproject()`. Switching between math.gl, proj4js and D3 changes the factory,
not the rendering code. See the [adapters and shared output handling](https://github.com/visgl/math.gl/tree/master/website/src/components/external-projection-engines).

```typescript
const engine = createExampleEngine(backend); // math.gl, proj4js or D3
const projection = await prepareMap(engine, 'equalEarth');
const xy = projection.project([12, 55]);
const longitudeLatitude = projection.unproject(xy);
```

Choose Mercator, [Equal Earth](https://d3js.org/d3-geo/cylindrical#geoEqualEarth),
[Albers Equal Area or Lambert Conformal Conic](https://d3js.org/d3-geo/conic), or
[polar stereographic](https://d3js.org/d3-geo/azimuthal#geoStereographic). All presets
use a sphere of radius 6,378,137 metres, zero false easting and northing, and
north-positive Y. The conic presets use standard parallels of 20° and 50° and
an origin of 0° longitude, 0° latitude. Stereographic is centered on the North
Pole with a scale factor of 1. D3's scale, rotation, center and Y direction are
configured to match the same point formulas in metres.

The map fits each projection to the view while the coordinate table shows the
engine's original metre coordinates. The graticule extends to 80° north; its
southern limit is 80° south for Mercator and Equal Earth, 60° south for the conic
presets, and 50° south for stereographic. These limits keep the view away from
polar singularities while including all 1,000 cities.

For general lines and polygons, use clipping, antimeridian splitting and
resampling; see [D3's streaming pipeline](https://d3js.org/d3-geo/stream).

proj4js and D3 are website dependencies only. Published math.gl packages do not
acquire them. proj-wasm has an asynchronous execution API and is covered separately
in the [external-engine guide](/docs/modules/geospatial/projection/developer-guide/external-projection-engines).
